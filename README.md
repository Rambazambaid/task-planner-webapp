# Планировщик — frontend

React + TypeScript + Canvas 2D + Zustand. Сборка — Vite, линтер — Oxlint.

## Запуск

Из папки `webapp/` (Node.js 22.12+ либо совместимая более новая версия):

```sh
npm ci
cp .env.example .env
npm run dev
```

Откройте адрес из вывода Vite (обычно http://localhost:5173). Бэкенд запускается отдельно по инструкции в `../backend/README.md`.

## URL бэкенда через env

```dotenv
BACKEND_URL=http://localhost:8080
VITE_GRAPHQL_URL=/graphql
```

- `BACKEND_URL` — адрес Go API для прокси Vite в режимах `dev` и `preview`. Запросы `/graphql` перенаправляются на этот адрес. Параметр не попадает в браузер. Так фронтенд и API работают без изменения CORS бэкенда.
- `VITE_GRAPHQL_URL` — конечный URL GraphQL, используемый браузером. По умолчанию `/graphql`. Можно задать абсолютный URL, например `https://api.example.com/graphql`; в таком случае сервер должен разрешать origin фронтенда через CORS.
- `VITE_*` встраиваются в JS во время сборки и публичны. Не передавайте через них пароли и токены. Изменив env, перезапустите Vite; для production пересоберите приложение.
- Для публикации статических файлов из `dist/` настройте reverse proxy `/graphql` на API либо задайте абсолютный `VITE_GRAPHQL_URL` при сборке. `BACKEND_URL` не конфигурирует внешний nginx автоматически.

Пример другого адреса API:

```sh
BACKEND_URL=http://127.0.0.1:18080 npm run dev
```

## Работа с доской

- Новая доска содержит одну пустую карточку.
- `+` справа создаёт следующий этап (`NEXT`), снизу — условие (`CONDITION`). Если исходящая связь такого типа уже есть, соответствующий плюс скрыт.
- Карточки и соединения отрисованы на настоящем Canvas 2D. DOM используется для Header, Sideblock, форм и вспомогательных элементов управления.
- Перетаскивайте карточки. Фон, средняя кнопка мыши или пробел + перетаскивание перемещают доску. Колесо изменяет масштаб относительно указателя.
- Текст и комментарий редактируются в боковой панели. Двойной клик по карточке переводит фокус в редактор.
- Кнопка «Показать всю доску» подбирает масштаб. Доступен диапазон 25–200%.
- «Сохранить доску» или ⌘/Ctrl+S записывает изменения через GraphQL в PostgreSQL.
- «Мои сценарии» открывает список первых 100 сохранённых досок.
- «Новая доска» создаёт новый черновик. При замене несохранённого черновика требуется подтверждение.
- Удаление карточки удаляет её связи; соседние карточки остаются. Последнюю карточку удалить нельзя.
- Действия добавления и выбора доступны с клавиатуры в Sideblock. На узком экране панель располагается под доской.

## Черновики и сохранение

Один текущий черновик автоматически сохраняется в `localStorage` через 250 мс после изменения. Это локальное сохранение, не подтверждение записи в БД. Браузер восстанавливает его при перезагрузке. Экспорт JSON позволяет скачать снимок; импорт JSON в этой версии не реализован.

Если API недоступен, редактирование остаётся доступным, а ошибка сохранения показывается явно. Во время записи на сервер редактирование блокируется. После каждой подтверждённой операции клиент запоминает реальные ID и версии сущностей; повторная попытка продолжает работу с этого состояния.

Сохранение всей доски состоит из нескольких GraphQL-операций и не является одной серверной транзакцией. Если связь потеряна после исполнения мутации, но до получения ответа, результат этой операции может быть неизвестен клиенту. Перед повторной попыткой проверьте серверную доску. Для полной защиты нужны серверные ключи идемпотентности или атомарная мутация графа.

Конфликт `expectedVersion` не перезаписывает данные автоматически: экспортируйте локальный черновик и откройте актуальную доску через «Мои сценарии». Авторизация отсутствует, как и в текущем бэкенде; приложение предназначено для локального или закрытого использования.

## Архитектура

| Слой | Содержимое |
| --- | --- |
| `src/domain` | Сущности и `BoardGraph`: правила связей, изменение графа, определение несохранённых изменений |
| `src/usecases` | `Editor`, `SaveBoard`, интерфейсы хранения и состояния |
| `src/adapters/api` | GraphQL-клиент и реализация репозитория |
| `src/adapters/state` | Zustand-store и адаптеры взаимодействия с ним |
| `src/adapters/storage` | Локальный черновик |
| `src/adapters/react` | Header, Sideblock, редактор и React-компоненты |
| `src/infrastructure/canvas` | Отрисовка, координаты, hit testing, мышь и клавиатура |
| `src/infrastructure` | Env-конфигурация и сборка зависимостей |

ООП и Zustand решают разные задачи. Классы инкапсулируют операции и детали реализации; Zustand хранит неизменяемые снимки общего состояния и уведомляет React/canvas. Доменные классы не зависят от React или Zustand. React-компоненты функциональные, с hooks; ООП применяется к модели, use cases, адаптерам и canvas.

Каждый класс ограничен 200 строками, включая пустые строки внутри объявления. `npm run lint` проверяет это по AST, вместе с Oxlint. Большие классы нужно делить по ответственности.

## Проверки

```sh
npm run lint
npm test
npm run build
```

Браузерные тесты:

```sh
npx playwright install chromium
npm run test:e2e
```

Если уже установлен Google Chrome:

```sh
PLAYWRIGHT_CHANNEL=chrome npm run test:e2e
```

Playwright поднимает Vite автоматически. Для теста с реальным API дополнительно задайте `E2E_REAL_BACKEND=1` и `BACKEND_URL`, указывающий на отдельный тестовый бэкенд. Остальные браузерные проверки выполняются без сервера.

Проверяются направления добавления, скрытие занятых плюсов, восстановление плюса после удаления, координаты при масштабировании, remapping серверных ID, повторная попытка после частичной ошибки, версии при одновременном изменении текста и координат, браузерный черновик и адаптивная верстка.
